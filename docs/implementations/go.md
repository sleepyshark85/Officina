# Go implementation

The second implementation, in [`go/`](../../go/): the same core, Claude and MCP packages, test kit, Bookshop Assistant
and samples as the .NET one, meeting the same [`REQUIREMENTS.md`](../../REQUIREMENTS.md) with the same acceptance
criteria. It is a rewrite from the requirements and the architecture, written as idiomatic Go, not a translation of
the C#. Working rules: [`go/CLAUDE.md`](../../go/CLAUDE.md). Plan: [`docs/plan/phase-1.md`](../plan/phase-1.md), the Go
column.

The owner approved the plan's recommendations on 2026-10-09, so these decisions stand. Go S01 and Go S02 check every
library named here before anything depends on it; one that fails is replaced through a PR to this page.

| # | Fills in | Decision | Reason |
|---|---|---|---|
| G1 | D1, TEST-03 | The newest stable Go when Go S01 starts, pinned in `go.mod` (`go` and `toolchain` lines); CI on Linux and Windows, like .NET. | Same reach as .NET |
| G2 | D8 | One module, `github.com/sleepyshark85/officina/go`. Package names are short and lowercase, not `Sleepyshark.Officina`: `officina` (core), `officina/claude`, `officina/mcp`, `officina/officinatest` (test kit, named like `net/http/httptest`). Bookshop Assistant is `cmd/bookshop` with its code in `internal/bookshop`; samples are in `examples/`. Release tags carry the module's directory: `go/v0.1.0`. | Go names packages by what they provide; the module path carries the owner |
| G3 | Core layout | The core is **one package**, one file per concept (`agent.go`, `run.go`, `conversation.go`, `tool.go`, `pipeline.go`, `memory.go`, `audit.go`…), not a package per .NET folder. A sub-package only when it has its own user and no cycle back. | Go packages are units of API, not folders of types; splitting the core early creates import cycles and exported internals |
| G4 | MDL-02, TEST-05 | The official Anthropic Go SDK (`github.com/anthropics/anthropic-sdk-go`), imported by `officina/claude` only; a test lists every package's direct imports (`go list -f '{{.ImportPath}} {{.Imports}}' ./...`) and fails otherwise. Direct, not `-deps`: the application imports `claude`, and the OpenTelemetry API pulls in modules of its own. Go S02 proves the beta features on it. | As .NET; the SDKs differ in what beta features they expose |
| G5 | D15 | **No dependency injection container.** Each package exposes constructors (`claude.New(…)`, `mcp.Connect(ctx, …)`) that take their dependencies explicitly; the application wires everything in one composition root (`main` calling `internal/bookshop.Build`), and tests call the same function with boundary fakes. | Go's convention is explicit wiring; a container would hide what `main` builds |
| G6 | D15, EVT-02 | Besides the standard library, the core imports only the OpenTelemetry API packages (`go.opentelemetry.io/otel/trace`, `…/metric`, `…/attribute`, `…/codes`, and the API's own no-op providers under `…/trace` and `…/metric`), never the SDK, an exporter or the semantic convention packages (`…/semconv/…`). The host passes a `TracerProvider` and `MeterProvider` in; without them the core emits nothing. The core never uses the global provider. Logs, where the core needs any, use `log/slog`. Its tracer and meter are named `Sleepyshark.Officina`, as .NET's activity source and meter are. | Go's standard library has no tracing or metrics; OpenTelemetry tells libraries to depend on the API only. `codes` (Go S07) is the API's span status, part of the same module as `attribute`, and the only way to mark a span failed. The semantic convention packages are left out: the attribute names must match .NET's string for string, and the generative-AI conventions are still in development, so each `semconv` version names them differently; the core spells them as constants |
| G7 | Q1 | `pgx` (`github.com/jackc/pgx/v5`), with `pgxpool`; plain SQL, no object mapper. | The plain driver, as in .NET |
| G8 | Q2, TEST-08 | The core's own small validator, ported; `github.com/santhosh-tekuri/jsonschema/v6` as the reference validator, in tests only. | As .NET |
| G9 | AGT-06, MDL-05 | `encoding/json/v2`, stable since Go 1.27; provider content blocks are kept as `jsontext.Value` in one canonical form (compact, `<` `>` `&` escaped, other escapes as received). Conversation JSON stores each block's JSON as a JSON string (`"raw":"{…}"`), the same format as .NET, so the bytes survive any store and the shared golden files apply (see the plan). `jsontext.PreserveRawStrings(true)` applies only where the Claude adapter writes a block as a JSON value into a request, so the SDK replays it unchanged (Go S02, Go S04). | Byte-exact replay and TEST-02 need bytes nobody re-encodes; v2 rejects duplicate names and invalid UTF-8, which v1 lets through |
| G10 | EVT-01 | A run returns its events as an `iter.Seq[RunEvent]` and its result after the sequence ends; stopping the loop early (`break`) cancels the run's tools and waits for them, as the .NET event stream does. Cancellation is a `context.Context`, always the first parameter. | Range-over-func iterators are Go's pull-free stream; `break` gives the "host stopped reading" signal without a leaked goroutine |
| G11 | TEST-01, TEST-07 | The standard `testing` package with `github.com/google/go-cmp` for comparisons; property tests with `pgregory.net/rapid` (failures print a reproducible seed); `go.uber.org/goleak` in every package's `TestMain`; `testing/synctest` for anything timed: its fake clock is the clock boundary, so there is no clock interface; `testcontainers-go` for PostgreSQL. No assertion framework. | Standard-library first; goleak and the race detector catch the concurrency bugs Go makes easy |
| G12 | Quality gates | `gofmt`, `go vet`, `golangci-lint` with the linter set in `go/.golangci.yml`, `govulncheck`, `go mod tidy` with no diff, `go test -race`; mutation testing with `gremlins` v0.6.0 (December 2025; Go S01 checked it runs on Go 1.27, so the `go-mutesting` fallback is not needed). gremlins tests each mutant in a copy of `go/` alone, so the tests find the shared `testdata/` through `OFFICINA_TESTDATA` (set by `go-mutation`); until Go S08 they did not, every test reading a fixture failed, and every covered mutant of the core and the Claude package counted as killed (Go S05's 99.7% efficacy was that). The honest baseline at Go S08, over the core, the test kit and the Claude package, after killing the survivors that could be: 99.1% test efficacy (427 killed, 4 lived, each an equivalent mutant or a file close that cannot fail after a sync), 83.4% mutant coverage (82.5–84.7% over runs since Go S05). `go-mutation` fails below 95% efficacy or 75% mutant coverage, set in `go/.gremlins.yaml` (v0.6.0 ignores the threshold flags): a few new survivors pass, a dozen do not; the coverage floor sits below its swing. A push to `main`, the weekly run and a manual one mutate everything; a pull request mutates only the lines it changed under `officina/` (`--diff`, which works once gremlins starts in `officina/` and `git`'s `diff.relative` makes the diff's paths match the ones it gives mutants; from `go/` it skipped every mutant), skips the run when it changed no code there, and passes when its changed lines hold no mutant. The pull request keeps both floors, as .NET's fails below its break threshold: a survivor in the changed lines is its author's to kill while the change is fresh, rather than one found after the merge. On a small change a single survivor fails it. | The tools the Go community and its style guides expect |
| G13 | Principle 11 | Core line budget: **3,500 code lines** (lines of the core package's non-test files that hold code, not only blanks or comments), enforced by `TestCoreSize_StaysWithinItsLineBudget`. Set at Go S03 as an estimate (about 1.5 times .NET's finished core of 2,356 code lines) and kept when revisited at Go S08 (1,978 lines then). A cut to 3,000 was tried and undone: Go S09 alone takes the core to 2,604, with context management (Go S10, about 120 more) and typed output (Go S12; .NET's output code alone is about 350 lines) still to come. | A budget needs a measurement |
| G14 | NS-13 | Hosting helpers, when they enter, target `net/http`. | Standard library first |
| G15 | TEST-03, required checks | `.github/workflows/go.yml` runs on every PR, with no path filter, and exits early when nothing of Go changed (`.github/changes.py`: `go/`, its spike, its workflow or the shared `testdata/`), as jobs `go-ubuntu`, `go-windows`, `go-quality` and `go-mutation`; the .NET workflows do the same for .NET. Branch protection requires all eight once Go S01 is merged. | A required check skipped by a path filter never reports, so the PR could never merge |
| G16 | D11, APP-20, TEST-06 | Bookshop Assistant exports with the OpenTelemetry SDK (`go.opentelemetry.io/otel/sdk`, `…/sdk/metric`, `…/sdk/log`) and its OTLP/gRPC exporters (`…/exporters/otlp/otlptrace/otlptracegrpc`, `…/otlpmetric/otlpmetricgrpc`, `…/otlplog/otlploggrpc`) to the compose file's Aspire dashboard, and logs through `log/slog` with the `go.opentelemetry.io/contrib/bridges/otelslog` handler. The core's tests use the SDK's in-memory exporter and manual reader. All in `internal/bookshop`, `cmd/bookshop` and tests, never the core (G6). | The standard library has no OTLP; the SDK and exporters are OpenTelemetry's own. gRPC, as the dashboard's port in the shared compose file speaks it (.NET's exporter does too) |
| G17 | BUD-01, BUD-02, APP-14 | Money is `float64` US dollars: prices per million tokens (`Price`, since Go S07), costs, budgets (`Limits.Cost`) and the session totals the application stores in the shared `numeric` columns. .NET uses `decimal`. A cost is an integer token count times a price, so each is within an ulp of exact, and a session's few hundred calls add up to within $1e-12 of it, far below the four decimals the console shows; a budget's output limit is a whole number of tokens floored from the remaining cost, so rounding can only lower it, and the overshoot bound (TEST-07) holds. Tests compare costs to $1e-12. | The standard library has no decimal type; a third-party one, or a fixed-point type of the core's own, would buy precision nobody can see, at the cost of a dependency or an API every host must convert to |
