# Ruby implementation

The third implementation, in [`ruby/`](../../ruby/): the same core, Claude and MCP packages, test kit, Bookshop
Assistant and samples as the .NET and Go ones, meeting the same [`REQUIREMENTS.md`](../../REQUIREMENTS.md) with the
same acceptance criteria. It is a rewrite from the requirements and the architecture, written as idiomatic Ruby, not a
translation of the C# or the Go. Working rules: [`ruby/CLAUDE.md`](../../ruby/CLAUDE.md). Plan:
[`docs/plan/phase-1.md`](../plan/phase-1.md), the Ruby column.

Proposed 2026-10-10; the owner chose R12 (Minitest), R13 (mutant, once the repository is MIT-licensed) and R18 (RBS
and Steep). Ruby S01 and Ruby S02 check every library named here before anything depends on it; one that fails is
replaced through a PR to this page.

CI on Linux and Windows, like .NET and Go. | Same reach as the others; one pinned version for everyone |
| R2 | D8 | One Bundler workspace in `ruby/` (one `Gemfile`, the gems as `path:` entries), four gems named by the RubyGems guide (a dash is a namespace): `sleepyshark-officina` (core, `Sleepyshark::Officina`, required as `sleepyshark/officina`), `sleepyshark-officina-claude`, `sleepyshark-officina-mcp` and `sleepyshark-officina-testing` (the test kit). Nothing is published to RubyGems in phase 1. | The owner prefix of D8 in Ruby's own naming convention; `officina` alone is a global gem name we do not own |
| R3 | Core layout | The core is **one gem**. One file per public class or module, named after it in snake case under `lib/sleepyshark/officina/` (`agent.rb`, `run_engine.rb`, `conversation.rb`, `tool_pipeline.rb`…), loaded with `require_relative` from the gem's entry file; small value types used only by one class nest in it. Internals are `private_constant`. No autoloading. | Ruby's convention maps constants to files; explicit requires keep load order visible without a dependency (Zeitwerk) |
| R4 | MDL-02, TEST-05 | The official Anthropic Ruby SDK (the `anthropic` gem, version pinned exactly), required by `sleepyshark-officina-claude` only, through its beta messages API. The dependency test parses every gem's `lib/` with Prism (in Ruby's standard library) and reads every gemspec, and fails when a gem requires or depends on anything R6 does not allow it; the test itself, outside the gems, is the only user of Prism. Ruby S02 proves the beta features on it. | As .NET and Go; Prism finds `require` calls without running the code |
| R5 | D15 | **No dependency injection container.** Each gem exposes constructors taking their dependencies as keyword arguments (`Claude::Model.new(client:, …)`, `Mcp.connect(…)`); the application wires everything in one composition root (`Bookshop.build`, called by `exe/bookshop`), and tests call the same method with boundary fakes. | Ruby's convention is explicit wiring; a container would hide what the application builds |
| R6 | D15, EVT-02 | What each gem may require, which the dependency test (R4) enforces: the **core**, the standard library, `json` and `bigdecimal` (a bundled gem since Ruby 3.4, so declared in its gemspec), `opentelemetry-api` (traces, stable) and `opentelemetry-metrics-api` (metrics); the **Claude** gem, the core and `anthropic`; the **MCP** gem, the core and the standard library (`net/http`, `Process.spawn` with pipes); the **test kit**, the core, the standard library and Minitest, whose tests its helpers extend, its fake MCP server speaking Streamable HTTP on a small `TCPServer` of its own, as Ruby's standard library has had no HTTP server since 3.0. The core never requires an SDK, an exporter or a semantic-conventions gem. The metrics API is still 0.x and marked experimental, so it is pinned exactly (0.9.0 at Ruby S01) and rechecked at Ruby S07. The host passes a tracer provider and a meter provider in; without them the core uses the API's no-op ones and emits nothing. The core never reads `OpenTelemetry.tracer_provider` or any other global. Tracer and meter are named `Sleepyshark.Officina`; attribute names are constants spelled as .NET's. Logs, where the core needs any, take a host-passed `Logger`. | OpenTelemetry tells libraries to depend on the API only; EVT-02 needs metrics, and the experimental API is the only one Ruby has |
| R7 | Q1 | `pg`, with `connection_pool` in the application only; plain SQL, no object mapper (no Active Record, no Sequel). | The plain driver, as in .NET and Go |
| R8 | Q2, TEST-08 | The core's own small validator; `json_schemer` as the reference validator, in tests only. | As .NET and Go |
| R9 | AGT-06, MDL-05, CTX-01 | The standard `json` gem, parsing with `allow_duplicate_key: false`, as it accepts duplicate names by default. Provider content blocks are kept as frozen UTF-8 strings of raw JSON in the one canonical form (compact, `<` `>` `&` escaped, other escapes as received), written by the core's own small function; conversation JSON stores each block as a JSON string (`"raw":"{…}"`), the format of .NET and Go, so the shared golden files apply. The `anthropic` gem keeps no raw block JSON and re-encodes its typed `messages` parameter ([Ruby S02](../../ruby/docs/spikes/claude-features.md)), so the Claude gem writes each response block from the gem's `to_json` into the canonical form, and sends the stored messages as `JSON::Fragment`s through the one raw request field, `request_options: {extra_body: {messages: …}}`, which goes out byte for byte. The prefix fingerprint is written by a small JSON writer in the core that escapes as .NET's default encoder does (uppercase `\uXXXX` for non-ASCII and HTML-sensitive characters), with tool schemas written as given, pinned by `testdata/session/prefix.json`. | Ruby's JSON generator escapes differently, so the bytes the fingerprint and replay need are written by the core, never re-encoded |
| R10 | EVT-01, AGT-05 | `Agent#run` yields each event to the block it is given and returns the result; leaving the block early (`break`, an exception) cancels the run's tools and waits for them before returning. Cancellation is a small token in the core (`Officina::Cancellation`: `cancel`, `cancelled?`, a callback on cancel), passed as the `cancel:` keyword, as Ruby has no standard one. A signal trap never calls it, as a `Mutex` raises in trap context: the trap pushes to a `Thread::Queue`, and a thread the application owns reads it and cancels. Never `Thread#raise`, `Thread#kill` or `Timeout.timeout`, which interrupt code at any point. | A block is Ruby's push stream; `break` is the "host stopped reading" signal; cooperative cancellation is the only safe kind with threads |
| R11 | TOOL-03, AGT-04 | Concurrency with the standard library's threads, `Thread::Queue` and `Mutex`; no fiber scheduler (`async`) in the core. The read tools of one reply each run in a thread and are joined before their results are appended; they overlap because I/O releases the global VM lock. Every thread has an owner that joins it; a test helper fails any test that ends with more threads than it started (the role `goleak` has in Go), so tests run one at a time, in random order; concurrency is proven by tests that start their own runs in parallel (AGT-04). An agent's definition (instructions, tool list, settings) is frozen once built; the collaborators it holds (model client, memory store, audit sink, telemetry providers) keep their own state and are thread-safe, guarding it themselves. | Threads are the standard library's concurrency and enough for I/O-bound tools; a fiber scheduler would push a dependency and a runtime choice onto every host |
| R12 | TEST-01, TEST-07 | **Minitest** (owner's choice; a bundled gem, so named in the `Gemfile`), plain `assert_*` assertions, no matcher library; property tests with `pbt` (shrinking, and a seed it takes and prints on failure: CI sets it through `PROPERTY_SEED`). Ruby S01 checked the planned `prop_check` 1.0.2: it draws from an unseeded `Random.new` per property and prints no seed, so a failure cannot be reproduced; its fallback `rantly` 3.0.0 takes no seed either (it draws from the global `Kernel#rand`, so only a whole run's order seed repeats it) and prints none. Recorded HTTP served by a small local `TCPServer` in the tests, not `webmock` (Ruby S04: a cut connection is then what the client really sees, and no dependency is added). PostgreSQL in Docker through a test helper that runs the compose file's database image with the `docker` command, once per run, each test on its own copy of the seeded database: Ruby S06 found `testcontainers-postgres` unmaintained (its last release, 0.2.0, in February 2024; the repository has had only dependency bumps since), and the helper needs no gem. The clock is a boundary: whatever reads the time takes a `clock:` (a callable), real by default, fake in tests. | Minitest ships with Ruby, matching "standard library first" |
| R13 | Quality gates | RuboCop with `rubocop-minitest`, `rubocop-performance` and `rubocop-rake`, configured in `ruby/.rubocop.yml` (any rule turned off says why); `# frozen_string_literal: true` in every file; Steep (R18); tests run with warnings on, and a warning about a file of the workspace fails them (a gem's is printed: the pinned `anthropic` warns as it loads, through `standardwebhooks`); `bundler-audit` for known vulnerabilities, in `ruby-quality` only, as it fetches its database; SimpleCov coverage reported, not gated, like .NET. Mutation testing with **mutant** and `mutant-minitest`, free under its licence for open-source projects: it needs the repository under an open-source licence (MIT, its own PR) and listed in mutant's subscription settings by the owner. Ruby S01 checked that mutant 0.17.0 with `mutant-minitest` runs on Ruby 4.0.7 with `usage: opensource`. It runs each gem that has a `mutant.yml`, with `PROPERTY_SEED` fixed, as kills are not repeatable without it. On a pull request it mutates only the subjects (methods) the change touched (`--since` its base), and any survivor fails it: an equivalent mutant is removed by changing the code, or its method is excluded with a `mutant:disable` comment saying why, which the review judges. On a push to `main`, weekly and on demand it mutates every subject and fails below 99% coverage: Ruby S05 measured 99.47% on the whole core (5,478 mutations), and the bar only rises. The core's `mutant.yml` counts a test process that aborts (mutant sets `Thread.abort_on_exception`, so a mutation that makes one of a run's threads raise ends the process) and a mutation timeout (a run that waits forever) as kills, and turns Ruby's warnings off while mutant inserts a mutation (`test/mutant_hooks.rb`): a mutated method that warns as it is parsed made the workspace warning check raise during the insertion, which mutant counted as a survivor without running a test. | The tools Ruby projects expect; mutant is the only maintained Ruby mutation tester |
| R14 | Principle 11 | Core line budget: **2,800 code lines** (lines of the core gem's `lib/` that hold code, not only blanks or comments), enforced by `test/core_budget_test.rb`. Set at Ruby S03 by measurement: its core is 412 code lines, 0.9 times Go's 451 at Go S03 (which had no loop yet), and Go's finished core is about 3,100. | A budget needs a measurement; the estimate of 2,500 before it assumed Ruby would need fewer lines than it does, as `end` lines and one file per class count |
| R15 | TEST-03, required checks | `.github/workflows/ruby.yml` runs on every PR with no path filter, and skips its jobs when nothing of Ruby changed (`.github/changes.py`: `ruby/`, its spike, its workflow or the shared `testdata/`); its jobs are required checks ([conventions](../conventions.md#required-checks)). The hooks run the Ruby checks for files under `ruby/` only, and the .NET checks no longer run for them. | As G15: a required check skipped by a path filter never reports |
| R16 | D11, APP-20, TEST-06 | Bookshop Assistant exports with the OpenTelemetry SDK gems (`opentelemetry-sdk`, `opentelemetry-metrics-sdk`, `opentelemetry-logs-sdk`) and the OTLP exporters to the compose file's Aspire dashboard, over OTLP/HTTP, as Ruby's OTLP exporters speak HTTP: the compose file gains the dashboard's HTTP port beside its gRPC one, which changes nothing for .NET and Go. Logs through `Logger`, bridged to OpenTelemetry; the logs SDK, like the metrics API (R6), is pre-1.0, so it is pinned exactly and rechecked at Ruby S07. The core's tests use the SDK's in-memory span exporter and metric reader. All in the application and tests, never the core (R6). | The exporters are OpenTelemetry's own; Ruby has no maintained OTLP/gRPC exporter |
| R17 | BUD-01, BUD-02, APP-14 | Money is `BigDecimal` US dollars: prices per million tokens, costs, budgets and the session totals in the shared `numeric` columns. | Exact like .NET's `decimal`; it ships with Ruby, and `pg` decodes `numeric` into it through a type map (`PG::BasicTypeMapForResults`), never left as a string |
| R18 | Types | **RBS signatures** (owner's choice) for every gem's public API in its `sig/`, checked by Steep in `ruby-quality` and the commit hook; the contracts (model, tool source, approver, memory store, audit sink) are RBS interfaces (`_Approver`…), which any object with those methods satisfies. Gem signatures through `rbs collection`, its lock file committed. Internals need no signatures. | Ruby's own signature format; typed contracts at the boundaries without changing how Ruby code is written |
| R19 | TOOL-01, OUT-01 | Ruby has no parameter types to derive a schema from, so a tool's input (and a typed output) is declared with a small schema DSL in the core: `Officina::Input.define { string :title, "Part of the title", optional: true; integer :max_price, minimum: 0 }` returns a `Data` class whose instances the handler receives, and its JSON schema, in the Q2 subset, with keys ordered and strings escaped as .NET writes them, so the Bookshop schemas match .NET's bytes and sessions resume across implementations. | The declaration is the type: one source for the value class and its schema, without reflection or runtime parsing of RBS (which carries no descriptions or constraints) |
| R20 | NS-13 | Hosting helpers, when they enter, target Rack. | Rack is the interface every Ruby web server speaks |
