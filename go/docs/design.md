# Go design notes

Choices in the Go core that the code alone does not explain. Concepts are in
[`ARCHITECTURE.md`](../../ARCHITECTURE.md); decisions G1…G17 in [`go.md`](../../docs/implementations/go.md).

| Choice | Why |
|---|---|
| `Agent.Stream` returns `(iter.Seq[RunEvent], func() (Result, error))`; `Agent.Run` is `Stream` without the events | G10. The two closures hold the context, so nothing stores it in a struct. The run happens inside the consumer's `range`, so the core starts no goroutine of its own; a `break` stops ranging the model's stream, which releases what it started, and the run's own context is cancelled as it returns |
| The `error` is only for misuse (blank message or context, a conversation in use); the run's outcome is the `Result` | AGT-03 and go/CLAUDE.md: model behaviour is a result, not an error |
| `Result` is one struct with a `Status`, not three types | Every result carries usage, and a struct compares with `cmp.Diff` and has a useful zero value; `Stop` and `Failure` are set only for their status |
| A reply and the messages it answers are all appended before any `ConversationAppended` is yielded | A host that stops reading after the first append still holds a valid conversation: the user message never stands without its reply |
| A cancel seen before the reply's `Finished` drops the reply, even if the model ignores the context | AGT-05: a reply cut off mid-stream is not appended. The core checks the context after every model event |
| Conversation JSON is .NET's form: a block's raw JSON is a JSON **string** (`"raw":"{…}"`) | G9 (the same format as .NET, for the shared golden files and cross-implementation resume). The raw bytes come back exactly however a store or encoder rewrites the outer JSON (indent, canonicalize, HTML-escape: all tested), so the core needs no encoder options for them. `jsontext.PreserveRawStrings(true)` matters where a block is written as a JSON value, which is the Claude adapter's request (Go S04) |
| A `Tool` is a plain struct with its handler, `func(ctx, jsontext.Value) (string, error)`; `NewTool[In, Out]` builds one from a typed function | The handler sees the input exactly as the model wrote it, once validated. A struct of exported fields is what a host can build itself, also for MCP tools (Go S11); the generic constructor is the only place `reflect` derives a schema: properties named as `encoding/json/v2` names them, required unless `omitempty`/`omitzero`, described by a `jsonschema` tag, and refused for types whose JSON has no schema in the subset (interfaces, bytes, embedded structs, `time.Duration`, types that marshal themselves) |
| `ToolKind`'s zero value is neither `Read` nor `Write` | TOOL-03: every tool declares its kind; a forgotten one would otherwise run concurrently and unaudited-first as a read |
| The tool pipeline runs on a goroutine of its own and hands its events to the run over a channel sized calls × 4 (started, approval asked and answered, finished) | The run, on the consumer's goroutine, yields them as they come while reads run concurrently. The pipeline never waits on the host, so a consumer's `break` only cancels the run's context, then the run drains the channel without yielding and waits: finished calls keep their results, the rest get "cancelled" results, and the results message is still appended (AGT-05) |
| A run makes at most 25 model calls, then stops with `IterationLimit` | AGT-03; the same bound as .NET, so a model that keeps calling tools cannot loop forever |
| The validator compares numbers as `float64` and runs `pattern` as a Go (RE2) regular expression | The reference validator in TEST-08 uses Go's `regexp` too, and RE2 is linear, so no timeout is needed. Integers beyond 2^53 lose precision in the validator only; the handler gets the original JSON |
| Redaction finds every occurrence of every form of every secret (as written, and as JSON may escape it) in the original text, merges the ranges that overlap or touch, and replaces each merged range once | D13: secrets that share characters (`abc` and `abcdef`, `abcd` and `cdef`, an escaped form against another's raw one) are redacted whole, whatever their order; replacing forms one by one, or longest first, leaves pieces behind |
| A panicking approver denies the call, its panic as the reason | The approver runs on the pipeline's goroutine, where the host cannot recover it |
| Audit kinds are `AuditRunStarted`…, written as `"RunStarted"`…; the JSON-lines sink writes a duration in nanoseconds | The tool events already own `ApprovalAsked` and `ApprovalAnswered`. `encoding/json/v2` has no default form for `time.Duration` and refuses `format` tags here, so the sink passes a marshaler for it |
| Model events and run events are sealed interfaces (`ModelEvent`, `RunEvent`) over small structs | A type switch reads like the contract; other packages can create the events but not add kinds |
| A retried model call is a `Retried` model event; the run drops the blocks of the failed attempt and tells the host with `ReplyRestarted` only if text had streamed | ARCHITECTURE 4.1 (a retry notice on every retry). The adapter yields each block as it completes, so a failure mid-stream can follow blocks the run already holds |
| A reply that calls tools is not appended while the run cannot run them (Go S04: no tool runs yet) | The provider rejects a `tool_use` without its result, so such a reply would break the conversation's next request. Go S05 runs the calls and appends the reply with their results |
| `claude.New(name, effort, Options)`: name and effort required, the rest optional | MDL-03: effort is never left to the model's default. `Options` holds the test seams too (`BaseURL`, `HTTPClient`), which are plain settings of the SDK client, so no interface is added for them |
| `Model.Settings()` is .NET's string word for word: `claude model=… effort=… max_tokens=… cache=5m thinking=adaptive` (cache `1h/5m` when the lifetimes differ) | Part of the prefix fingerprint: one string for both implementations lets Go S08 match .NET's fingerprint |
| Each message of a request is written as JSON by the adapter (`encoding/json/v2` with `PreserveRawStrings`, HTML and JS escaping) and sent through `param.Override`; the rest of the request is the SDK's typed params | G9: stored blocks then reach the wire byte for byte, as the SDK's encoder leaves the canonical form unchanged. The run context is a `system` message whose content is a string, as .NET sends it, so the shared golden layout applies |
| Blocks are stored in the canonical form: the accumulated block's JSON, compacted with `jsontext.Value.Compact` (escapes kept), then `<` `>` `&` U+2028 U+2029 escaped with `encoding/json`'s `HTMLEscape` | The fixed point of the SDK's encoder (Go S02); a tool call's `Input` keeps the model's own text, from the union's raw `Input` |
| Retries are the adapter's own (the SDK's are off): five attempts, `Retry-After` (seconds or a date) capped at 30 s, else 1 s doubling with jitter; any error without an API answer (network, a stream cut short) is transient | MDL-04 mid-stream too: the SDK does not retry a stream that failed after it began. The wait is a timer in the stream's own goroutine, so nothing outlives `Stream`; tests run it under `testing/synctest` |
| Error classes are sentinel errors (`ErrTransient`, `ErrAuthentication`, `ErrInvalidRequest`) wrapping the SDK's error | `errors.Is` is how Go checks a class; the run reports the text in `Result.Detail` |
| Telemetry is built once per agent from `AgentOptions.TracerProvider` and `MeterProvider`, the API's no-op providers when nil; spans are started from the run's context, so a run is a child of the host's span in `ctx` and its model and tool spans are children of the run's | G6: no global provider. Contexts carry the span the Go way, so a tool's handler and the model's stream see the step's span too. A test, or two agents, can each have their own providers |
| An audit entry takes its trace and span from the context it is recorded with (`trace.SpanContextFromContext`): the tool call's for a call's entries, the run's for its start and end; a failed write marks that same span and counts `officina.audit.failures` | AUD-03, AUD-06, as .NET does it. Without a tracer provider a host's span in `ctx` still names the trace, as the no-op tracer passes its parent on; without either, the ids are empty |
| `Model.Info()` gives the provider, model name and `Price` (dollars per million tokens, `float64`); `Usage.CacheWriteHour` counts the hour-long cache writes, which cost more | The span names, `gen_ai.provider.name` and `gen_ai.request.model` need them, and cost is on the run and model call spans, `officina.model.cost` and the run's end entry, as in .NET. Telemetry is `double` in .NET too; money stays `float64` for budgets as well (G17) |
| A host that stops reading ends the run as `Stopped(Cancelled)`, so Go has no "abandoned" run result in telemetry | G10: `break` cancels the run, which still returns its result; .NET's enumerator can be dropped without one |
| `RunOptions.Budget` is `Limits`, whose limits are pointers (nil for none, set with `new(…)`); the stop reason is `Budget` | A limit of zero is real: a session with nothing left gives its reply a cost budget of $0, which stops before the first call. The type is not named `Budget` so the stop reason can be, as in .NET and the audit's `Stopped: Budget` |
| The prefix fingerprint hashes bytes the core writes itself (`appendDotnetString`), not `encoding/json`'s output | A stored conversation carries the fingerprint, and one either implementation stored resumes in the other, so the bytes are .NET's `Utf8JsonWriter`'s: its default escaping (all of non-ASCII, the controls and `" & ' + < >` and backquote, upper-case hex), each schema as given. Checked on every code point against .NET once, and by the shared `testdata/session/prefix.json` |
| A run on a conversation whose last message is a reply with tool calls and no results first appends an "interrupted" error result for each, audited as `ToolEnded` with outcome `interrupted`, and reports it as `ConversationAppended` | ARCHITECTURE §5: a crash while tools ran leaves that state, and the provider rejects calls without results; the text is .NET's, so the model reads the same in either implementation |
| A tool names its `ToolSource` (`Tool.Source`), a three-method interface (`Name`, `Connect`, `Changes`); the agent keeps its tools' distinct sources, told apart by `==`, and each run connects them before its first model call, then records their changes in the audit trail, and again after each reply's calls | ARCHITECTURE 4.2, D15: the host connects an MCP source while composing (`mcp.Connect`); each run checks it, reconnects one that was lost, and fails with `ToolSourceUnavailable` if it cannot. Telemetry's `officina.tool.source` is the source's name |
| `mcp.Connect(ctx, …)` works like `net.Dialer.DialContext`: ctx bounds the connecting, not the connection, and `Source.Close` ends it | A source outlives the context it was connected with, and each run checks it with its own. `Close`, or a failed connect, closes a stdio server's input, so it can exit by itself (as a container must), kills it with every process it started 5 s later, and returns once `Wait` has, so no process, zombie or goroutine outlives the source |
| A stdio server is stopped with every process it started: on Unix it leads a process group of its own (`Setpgid`), killed whole when it does not exit, and what is left of the group is killed once it has; on Windows `taskkill /T /F` kills its tree | Servers are usually started by a launcher (`npx`, `uvx`, `docker run`, a script), so killing the launcher alone would leave the real server running, as .NET's `Kill(entireProcessTree: true)` avoids. The standard library has no Windows job objects, so on Windows a process whose parent has already exited is not found, and is not stopped. A process group also keeps the terminal's Ctrl+C, meant for the reply, from reaching the server |
| A server's message is at most 16 MB: a longer stdio line stops the server, and a longer HTTP answer (with what precedes it in an event stream) loses the connection | A server that sends without line ends, or without end, would otherwise exhaust memory |
| The source redacts its server's credentials by merging the ranges every credential covers, as the core does | One credential that starts with another would otherwise leak its tail; the core's redaction is unexported, and sharing it would add core API for one user |
| The stdio transport has one goroutine of its own, waiting for the process; the server's output reaches a line splitter through `exec`'s own copying, and each response goes to the request waiting for its id | Calls may overlap on one connection. `Wait` returns only once the output is read, so the last line of the server's error output can say why it ended |
| The Streamable HTTP transport has an `http.Transport` of its own | Closing the source frees its idle connections, so none outlives it (`goleak`) |
| An MCP tool's error result is its handler's error; its schema is checked by `NewAgent`, not by `mcp.Connect` | A tool is a plain struct, and the core compiles every schema once, where a host's own tools are checked too |
| The fake stdio server of the MCP tests is the test binary, run again with an argument its `TestMain` reads | The `os/exec` tests' own pattern: no second program to build, on Linux and Windows |
| Typed output is `NewOutput[T]()`, an `*Output` in `AgentOptions`; a completed run's `Result.Output` holds a `T` (an `any`), which the host asserts | The agent is not generic, so the run cannot return a `T`; the schema is derived as `NewTool`'s (the one other place `reflect` is allowed), and a map anywhere is refused, as structured output needs named members. The reply's text is validated by the core's validator, then decoded with `encoding/json/v2`; a failure of either is `Failed(InvalidOutput)` with the problems, with no correction round (OUT-02) |
| The output schema is part of the prefix: `Request.OutputSchema`, fingerprinted as `,"output":<schema as given>` after the tools, as .NET does | A conversation started with typed output does not continue without it; checked against .NET's fingerprint in the shared `testdata/session/prefix.json` |
| The Claude adapter adjusts the output schema itself (`claude/output.go`): every object closed, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `maxItems` and a `minItems` above 1 left out, an open object refused; the rest kept in its order, and sent as `json.RawMessage` in `output_config.format` | Go S02: the SDK's schema helpers drop a schema with `type` as an array. Walking the members in order, rather than through a map, keeps the properties in the order the model writes them |
