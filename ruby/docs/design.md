# Ruby design notes

Choices in the Ruby code that the code alone does not explain. Concepts are in
[`ARCHITECTURE.md`](../../ARCHITECTURE.md); decisions R1…R20 in [`ruby.md`](../../docs/implementations/ruby.md); what
the Anthropic gem can and cannot do in [`spikes/claude-features.md`](spikes/claude-features.md). Each slice adds the
rows for the choices it makes, and fills in its rows of the runtime-model table below.

| Choice | Why |
|---|---|
| Four gems and the application in one Bundler workspace, with one `Gemfile.lock` | R2. Every gem is built and tested against the same versions, and one `bundle install` sets up everything |
| The dependency test reads the code without running it: each gemspec's runtime dependencies, and every `require` in a gem's `lib/` found with Prism. A `require` it cannot read (a computed path) fails it | R4, TEST-05. Loading the code would run it, and a dependency required only on some path would slip through; a computed `require` could hide anything |
| The test kit may depend on `minitest` | Its thread-leak check is a Minitest lifecycle module that asserts; nothing else in the library gems may use a test framework |
| A warning about a file of the workspace fails the tests; one about a gem's file is printed. Done by prepending a module to `Warning.warn`, loaded before anything else | R13. Ruby has no switch that turns warnings into errors; Warning.warn is its documented hook. The pinned `anthropic` gem warns as it loads, which the workspace cannot fix |
| The thread-leak check is a module included in `Minitest::Test` that compares `Thread.list` before setup and after teardown, so tests run one at a time | R11. Ruby has no goroutine-style leak detector; every thread a test starts must be joined before it ends. With parallel tests another test's threads would count |
| Property tests use `pbt`, seeded from `PROPERTY_SEED` when set, and print the seed on failure | R12, TEST-07. The planned `prop_check` and its fallback `rantly` take no seed, so a failure could not be replayed |
| Mutation testing runs from each gem's `mutant.yml` (the core's, the Claude gem's and the MCP client's) with `usage: opensource` | R13. mutant is free only for open-source projects, which the setting declares |
| Misuse and a broken environment raise `Sleepyshark::Officina::Error` (a blank message, a second run on a conversation, JSON that is not a conversation's); every way a run ends is a `Completed`, `Stopped` or `Failed` value with a reason symbol | ruby/CLAUDE.md, AGT-03. One error class until a host needs to tell two apart |
| Value types are `X = Data.define(…)`, reopened with `class X` when they need methods or a checking `initialize`; each one's `.rbs` declares its `new` with its members, and `ruby/sig/data.rbs` declares that `Data#initialize` takes keywords | Steep types neither the body of a `Data.define` block nor a keyword `super` to `Data#initialize`, which RBS's core signature leaves out. Declaring `new` per class keeps every constructor call checked |
| A `Data` member that is a flag is read through its predicate (`ToolResult#error?`); the member's own reader is private | `Data.define` defines a reader per member, and a predicate ends in `?` (ruby/CLAUDE.md): one reader for the flag |
| `Conversation` keeps its fingerprint and messages in one frozen private `State`, replaced by one assignment on each append | A host may read or save the conversation on another thread while a run appends; one reference means a reader never sees messages without their fingerprint |
| The model contract (`_Model` in `sig/…/model.rbs`): `settings`, and `stream(request, cancel:)`, which yields text deltas and usage and returns the `Reply` (blocks, stop, detail), or nil when the cancellation cut it off; a failure left after retries is raised | R10. A block is Ruby's push stream, and the whole reply is the stream's natural return value. The engine rescues `StandardError` around the stream, the boundary ruby/CLAUDE.md names, except an exception the host's own block raised, which passes through |
| `Conversation#hold` takes the conversation for one run with `Mutex#try_lock` and yields the only way to append; a second run, on any thread or from inside the first run's block, is refused | One run per conversation without a flag to reset: the lock is released in an `ensure`, `break` included. Reading and saving the conversation never takes it, so a host may save from its event block |
| A message and its run context are held as pending and appended with the reply; all of a step is appended before the first `ConversationAppended` is yielded | AGT-05, AGT-08, the event order of ARCHITECTURE §5.3. A host that leaves the block at the first event still holds a valid conversation |
| A block keeps its raw JSON as received, frozen; `Block.canonical` writes the canonical form for a provider adapter (Ruby S04), and the test kit's blocks use it. Empty text in a block with raw JSON or a tool result is no text | R9. Replay needs the exact bytes, so nothing re-encodes a stored block. The JSON form leaves such text out, so the round trip keeps blocks equal |
| The conversation's JSON is read with pattern matching, symbol keys and `allow_duplicate_key: false`; Steep's `@type var` comments type what a pattern binds | Pattern matching states the shape in one line per member and raises on any other; Steep does not infer pattern bindings |
| The prefix fingerprint is computed now, by the core's one writer of .NET's escaping (`DotnetJson`, which the DSL's schemas and `Block.canonical` use too), and pinned by `testdata/session/prefix.json`. Invalid UTF-8 is written as U+FFFD, never raised | R9. It cost about 20 lines, so a conversation bound in this slice already resumes in .NET and Go (Ruby S08). .NET's encoder replaces what it cannot encode the same way, and a description or name is never worth failing a definition for |
| `Cancellation` is a flag behind a `Mutex`; `on_cancel { … }` runs a block once, on the thread that cancels, or at once when it already is (R10). Its user is the Claude model's wait between attempts, a `Thread::Queue#pop(timeout:)` that the block closes | Cancelling wakes a wait at once, with no polling and no thread; the callbacks run outside the lock, so one may take locks of its own. Mutation testing leaves the two `synchronize` blocks, which no test can show racing under the global VM lock, and `@cancelled = false`, which every reader tests only for truth |
| TEST-02 across a restart runs a child Ruby process (`test/fixtures/resume.rb`) that builds the agent from the fixture the test builds it from too, resumes the conversation's JSON from standard input and writes back its result and, for each request, its instructions, messages and what of each tool reaches the model, with `Marshal`, which cannot dump a tool's handler; the prefix check compares tools by that part | A new process is the strongest form, as in .NET and Go; `Marshal` carries the requests back without a serializer written for the test |
| Tests follow `.rubocop_tests.yml`, which each test directory's `.rubocop.yml` inherits: a test method may run to 15 lines and make five assertions, and has no ABC size limit; a test class keeps the library's length limit | A test reads as one example: its setup, the call, then what it checks. RuboCop sets a cop's limits per configuration file, not per path, so the test limits sit in a file of their own. |
| Stored blocks are sent through the request's raw `messages` field (`extra_body`), each message as a `JSON::Fragment` of its canonical bytes, built with the stored blocks as fragments inside it; nilable block fields are read as `block[:field]` | R9, Ruby S02: the gem re-encodes typed messages, and raises when a nilable field set to `nil` is read through its accessor. One raw field, inside the Claude gem only; the typed parameters (tools, system, settings) go through the gem as usual |
| A reply block is stored as `Block.canonical(block.to_json)`, the gem's dump of its model; a tool call's input is `JSON.generate` of the input the gem decoded when the block ended | R9, Ruby S02: the gem keeps no raw JSON. The call's input then matches the stored block, which is what the model sees again; the model's own spacing is not kept by either |
| `Claude::Model.new` takes every setting as a keyword (`name:`, `effort:` required, MDL-03), and builds its own client with the SDK's retries off; `api_key:` and `base_url:` reach the SDK, which otherwise reads its environment as usual. Keyword arguments do not count towards RuboCop's `Metrics/ParameterLists` (`ruby/.rubocop.yml`), so the method needs no disable | R5. The host never touches an SDK object (MDL-02); the model's own retries replace the SDK's, as they must also cover failures mid-stream and tell the run of each. ruby/CLAUDE.md asks for a keyword per setting |
| `settings` is .NET's and Go's string: `claude model=… effort=… max_tokens=… cache=… thinking=adaptive`, the cache lifetimes as one word, or prefix's/conversation's (`1h/5m`) | The fingerprint (Ruby S08) must match theirs byte for byte |
| A call is retried with Ruby's `retry` in the `rescue` of `stream`, at most 5 attempts; before each new one the model yields `Officina::Retried`, a memberless value in the core, which the run passes to the host | ARCHITECTURE §4.1, §10: a notice on every retry; the reply is returned whole at the end, so nothing of a failed attempt but its streamed text and usage has reached the run, and the host discards the text |
| A failure is transient by the API's error type first (`overloaded_error`, `api_error`, `rate_limit_error`, `timeout_error`), then by status (408, 409, 429, 5xx); a connection error (a timeout included), and a stream that ends without its stop reason, are transient too; no other SDK error is (credentials it cannot find, an event it cannot read). What remains is a `Claude::TransientError`, `AuthenticationError` (`authentication_error`, `permission_error`, 401, 403, or the SDK's `ConfigurationError`) or `InvalidRequestError`, with the SDK's error as `cause` | An error event mid-stream arrives with the response's status, 200, so only its type tells. Three classes, as .NET's and Go's, so a host can tell a key problem from a bad request |
| The wait honours `Retry-After` in seconds, capped at 30, else backs off 1, 2, 4… seconds times a jitter of 0.5 to 1; a date form counts as none | The API sends seconds; reading a date would need the clock for one case it does not send |
| "Prompt is too long" (a 400 saying so) is a reply that stops for `:context_full`, read in the one place the gem reads an error's text | ARCHITECTURE §10; the API gives it no type of its own |
| The usage an attempt reported before it failed is yielded before `Retried`; a cancelled attempt reports none | The failed attempt's tokens are billed (ARCHITECTURE §4.1); a cancelled one's output count is unknown |
| The model checks the cancellation at each event of the stream and before each attempt; the wait between attempts wakes at once | The SDK reads the socket inside an enumerator's fiber, which no other thread may resume or close, and R10 rules out `Thread#raise`. A stream silent between events (thinking, as Opus 5.5 omits its text) ends at its next event, or at the SDK's 10-minute timeout. However the loop over the stream is left (a reply, a `break`, a raise, a cancel), the SDK's enumerator closes the connection in an `ensure`, so the model closes nothing itself; tests check it against a fake API that holds the connection open |
| The waits go through a `wait:` callable, the real one by default; tests pass one that records the seconds and returns | The clock is a boundary (R12): retry tests run in milliseconds and check each wait |
| The Claude gem's tests run against a fake API on a local `TCPServer` (`officina-claude/test/fake_api.rb`) that streams chunked responses, rather than `webmock` | No new dependency; a cut connection (no last chunk) and a clean end without a stop reason are what the client really sees, and each request's bytes are recorded as they arrived |
| Steep reads the few SDK and `JSON::Fragment` signatures the gem calls from `ruby/sig/anthropic.rbs` and `ruby/sig/json.rbs`, not the gem's own | With the gem's full signatures Steep took 2 min 20 s instead of 6 s, on every commit |
| `examples/*/*_test.rb` are part of the suite: `hello` runs on the fake API there, and live by hand | ruby/CLAUDE.md: each sample runs as a test |
| The memory store contract (`_MemoryStore` in `sig/…/memory_store.rbs`) has five methods, `list`, `read`, `write`, `delete` and `rename`, more than the one to three ruby/CLAUDE.md asks of a contract | ARCHITECTURE §4.4 names the five. A store's own `rename` checks the new path is free and moves the file under the store's lock in one step, so two runs on one scope cannot both claim a path (Go composes rename from write and delete in its memory tool) |
| `MemoryRules` holds the rules both stores apply: .NET's parts (no `.` or `..`, no trailing dot or space, none of `\ / : * ? " < > \| %` or control characters, no Windows device name); a scope, path or text must be a valid UTF-8 `String`. Unlike .NET, the limits count UTF-8 bytes rather than UTF-16 units: a path at most 1,024, a part 255, a scope 127 | MEM-03, TEST-07. A part can never climb or be absolute. File systems limit a name to 255 bytes (ext4), and the file store names a scope's directory by its bytes in hex, twice as long; the root's own length still counts against the system's limit on a whole path. A string never has fewer UTF-8 bytes than UTF-16 units, so Ruby accepts no path .NET refuses |
| Every refusal raises `Officina::Error` with a message naming what was refused; a missing file reads as `nil`, and deleting one does nothing | A refused path is the caller's misuse (ruby/CLAUDE.md); the memory tool (Ruby S09 part B) passes the message to the model as its error result. Both stores raise the same messages |
| `HashMemoryStore` refuses a path that is a directory of the scope's files, or runs through one of them, as a file system does | The two stores then behave the same, and one shared set of tests (`MemoryStoreContract`) runs against both. Named after Ruby's `Hash`, as Go's after its `map` |
| `FileMemoryStore` names each scope's directory by the hex of its UTF-8 bytes, and refuses a scope directory or any path part that is a link (`File.symlink?`, which on Windows covers junctions too); `Dir.glob('**')` never descends into a linked directory, so `list` skips what lies behind one | Scopes that differ in case stay apart; nothing outside the scope is reached even through a link inside it. It guards against the model's paths, not other processes changing the directory |
| `FileMemoryStore` reads and writes bytes (`File.binread`, `File.binwrite`) and checks the text is UTF-8 | On Windows the text modes translate line ends, so the same text would have different sizes and bytes per system |
| Each store holds one `Mutex` around every operation | Stores are shared across runs (§5.3, R11) and guard their own state: a rename's check and move, and removing a directory left empty while another run writes into it, never interleave. In the in-memory store the lock also guards each walk over the `Hash` (a list, the clash check of a write or rename) and the check-then-insert after it: without it a write during another thread's walk raises, and a check can pass on files that change before the insert. The contract tests show both stores' locks: eight threads in one directory fail at once without the file store's, and threads switched at every block call (a `TracePoint` calling `Thread.pass`) fail without the in-memory store's around a list, write or rename. Its `read` and `delete` are each one `Hash` call, which MRI's VM lock already makes whole, so removing their lock cannot be seen there; they keep it for other Rubies |
| The MCP client (Ruby S11, part A): `Mcp.connect(Mcp::Server, cancel:)`, its one entry point (a `Client` is made over a transport only it builds), returns a `Client` with `list_tools` (every page), `call_tool` and `close`. A server that cannot be started or reached, fails or goes away raises `Mcp::Error`, and the connection stays lost; one that answers a request with a JSON-RPC error, or a result it cannot read, raises it too, but keeps the connection; a tool's own failure is a `CallResult` whose `error?` is true. A tool list whose cursor comes back twice raises rather than loop | ruby/CLAUDE.md: a broken server is a broken environment, raised; a failing tool is a result. Part B turns the error into the run failing at connect, or into an error result mid-run (MCP-04) |
| A request waits in 50 ms slices, checking `cancel.cancelled?` and the 30 s connect deadline between; cancel is any `_Cancellation` (a `cancelled?` method). Every wait (the connect deadline, a server's 5 s to exit, the error output's 1 s) is measured on the `clock:` callable, monotonic by default, so tests move time instead of waiting for it | R10: cooperative. The client needs only `cancelled?`, which the core's `Cancellation` has, so part B passes the run's. A cancelled call raises without waiting for the server's tool. R12: a test of a 5 s wait takes milliseconds |
| Stdio: the program runs through `Open3.popen3` as `[program, program]` (no shell), in a process group of its own on Unix (`new_pgroup` on Windows). `ChildProcess` owns the process, its pipes and both reader threads: one reads the output and hands each line to `Stdio`, which gives each response to its request's `Thread::Queue`; one keeps the end of the error output, whose last line says why a server ended. `close` closes the input, waits 5 s for the exit, kills the server (`taskkill /T` on Windows, for what it started) until `popen3`'s waiter thread has reaped it, kills what is left of its group on Unix, then closes this side's output and error pipes at once, which ends both reader threads even when a stray process outside the group still holds a pipe: no second 5 s wait. The group is killed after the reap; as its leader is gone by then, its id could in principle be reused, which a group that is empty and an id reused within that instant would both need. A message is written whole, with no lock: it is one `IO#write` of one string, which MRI finishes before another thread's write to the same IO starts. A server that stops reading its input while one longer than the pipe's buffer is written blocks that write, whatever the cancellation, until the server ends. A server that cannot be written to is killed, so its output ends and says why. The error output is read a line at a time (at most 4,096 bytes of a line), and its last non-blank line is the error thread's value; the reason waits 1 s for it, so when a process the server started still holds the error output, the error says the server ended but not why | As Go's: a server stops by itself when its input ends, as a container must; the group catches what a launcher (`npx`, `uvx`) started. Every thread is joined (R11) |
| Streamable HTTP: one `Net::HTTP` connection per request, opened and read on a thread of its own, so the caller checks the cancellation and the connect deadline from the start. Cancelling closes the connection, which ends the blocked read with `IOError`, and joins the thread. A connection still opening cannot be closed: a request cancelled then waits for it to open or fail, at most 10 s (the open timeout). No read timeout: the run's cancellation ends a call. A notification waits for its 202 | `Net::HTTP` has no cancel, and `Thread#raise` is ruled out (R10); closing a socket from another thread is how Ruby ends a blocked read. One connection per request leaves no pool to manage |
| JSON-RPC and event-stream parsing (`Wire`, internal) is tested directly with generated streams (`pbt`), reached through `const_get`; a response is a message with a result or error, a positive integer id and no method; anything else a server writes is skipped. An event stream remembers how far it has searched for a line end, so a long line in many chunks is read in linear time. 16 MB is the most a server may send for one message: a line over stdio (its line end aside), the whole answer over HTTP | TEST-07. Hundreds of cases need no connection; the internals stay `private_constant` |
| Value classes that need methods (`CallResult`, `Server`, `FakeMcpTool`) are `Data.define` and then reopened, as every value type is | A `Data.define` block is not read by Steep as the class's body, so its methods would go unchecked |
| `Results` (internal) reads what `tools/list` and `tools/call` return: each value checked with `instance_of?`, as `JSON.parse` makes no subclasses, and each member read once with `values_at`; anything it cannot read is `nil`, which the client raises as an unreadable result. Lines Steep cannot type (`Open3.popen3`'s `[program, argv0]` form, `Net::HTTP`'s nil timeouts, a value broken out of `Net::HTTP#request`'s block) carry `# steep:ignore` with the reason beside them | One place decides what a result holds, so the client only sends and waits. The ignores are where the standard library's signatures leave a form out, never to pass a type the code gets wrong |
| The fake MCP server is `Testing::FakeMcpServer`: `#serve` speaks stdio, run by a fixture script the tests start with `--disable-gems`, so it starts in milliseconds; `#serve_http` speaks Streamable HTTP on a `TCPServer`, one request per connection, joined when its block ends. Its JSON-RPC side is a nested class; its HTTP front only reads requests and writes answers. What it never sends (answers that are not HTTP, results to refuse) comes from a scripted HTTP server of the MCP tests' own | R6: the standard library has no HTTP server. One tool per page, a notification before each result, and the headers and session the protocol asks for, as .NET's fake; stricter than a real server (JSON-RPC 2.0, params an object, the client's capabilities and info, its initialized notification before any tool, the agreed version on each request), so a client that leaves one out fails |
| A tool's input or a typed output is declared with `Input.define { … }` (R19), whose methods are the JSON types (`string`, `integer`, `number`, `boolean`, `array`) with `optional:`, `nullable:`, `minimum:` (integers only), `enum:` (strings) and `array … of:` or a block for objects; it returns a frozen `Data` class with `schema` and `from_json`. Two members with the same JSON name are an `ArgumentError`, and the block runs on an object with only the five type methods | Only what the Bookshop tools, its summary and the samples' outputs need. One declaration is the value class and the schema, so they cannot drift; an absent member is `nil`, and a handler applies its own defaults. An integer member given as `2.0`, which JSON Schema accepts, becomes `2`, as .NET's and Go's members are integers |
| A member's JSON name is its Ruby name in camel case (`max_price` is `maxPrice`) | .NET's tools take their parameter names and its outputs camel-case their members, and the schemas must be .NET's bytes, so Bookshop's names match without a per-member setting |
| Typed output is `Agent.new(output:)`, a class from `Input.define`, the declaration tools use. A completed run's text, once redacted, is parsed, validated against the class's `Schema` and read with its `from_json` into `Completed#output`; a reply that is not JSON or does not validate ends `Failed(:invalid_output)`, its detail every problem joined by "; " (text that is not JSON by the line and column where it breaks off only: the parser's message quotes the reply, and the detail reaches telemetry), and stays in the conversation. Done after the loop (`TypedOutput`, internal), so any other result passes as it is | OUT-01, OUT-02, GEN-05, R19. One declaration for input and output; reading the redacted text keeps secrets out of the value as out of the text, as Go does |
| The fingerprint's `output` part is the schema as given, after the tools, only when the agent has one, as .NET writes it; pinned by each `output` entry of `testdata/session/prefix.json`, whose schema the DSL writes byte for byte | CTX-01, CTX-04: a changed output type fails the run as a changed tool does |
| Claude gets the schema as `output_config: {effort:, format: {type: :json_schema, schema: Hash}}`, adjusted by `Claude::OutputFormat` (internal) as .NET and Go adjust it: `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `maxItems` and a `minItems` above 1 dropped, every object closed, an open object refused with `InvalidRequestError` before any attempt (the run fails `:model_error`). Tool choice is never forced | Ruby S02 (structured output row): the API rejects those keywords; the Hash keeps the schema's member order, which is the order the model writes. Checked against the shared `testdata/claude/output-written.json` |
| The schema is written as text by the DSL, not built as a hash and encoded: description first, then `type` (a list for nullable) or `enum` alone, then `minimum` and `items`; an object as `type`, `properties`, `required` (always, even empty), `additionalProperties: false`; strings escaped as .NET's default encoder does (`DotnetJson`) | The prefix fingerprint takes each schema as given, so a session one implementation saved resumes in another only if the schemas are the same bytes (Go S13 found this). Pinned against what .NET printed (`officina/test/fixtures/dotnet-schemas.tsv`) and the shared `testdata/session/prefix.json` |
| `Schema.new(json)` checks the subset when it is created and raises `SchemaError` naming where it leaves it; `#validate(value)` returns problems as `"<JSON pointer>: <problem>"`, as .NET and Go word them | TEST-08: nothing is half checked. A list of problems, not an exception, as invalid input goes back to the model as an error result it can act on |
| The subset is .NET's and Go's: the annotations, `type`, `properties`, `required`, `additionalProperties`, `items`, `anyOf`, `enum`, `const`, the four counts, `minimum`, `maximum`, `pattern` | The same schemas are accepted by every implementation, the DSL's and those MCP servers send |
| Numbers compare as Ruby compares them (an `Integer` and a `Float` exactly); 1.0 is an integer; string lengths count code points | Exact where .NET and Go use doubles; matches JSON Schema and the reference validator |
| A `pattern` is a Ruby regular expression with a 0.1 s timeout; one that times out is a problem of that value, not an error | Ruby has no ECMA-262 engine; its `^` and `$` match at line ends. The reference validator runs with Ruby regular expressions (`regexp_resolver: 'ruby'`) so the property test compares like with like |
| A `Tool` is a frozen class, not a `Data`: name, description, `input:`, `kind:` (`:read` or `:write`, required), `needs_approval:`, and the handler as the block, called with the input and the run's `Cancellation`. The input is a class from `Input.define`, whose value the handler gets, or a `Schema`, which is its own input type (`schema` is itself, `from_json` the JSON value as it is). A String result goes to the model as it is, a `ToolFailure` as an error result with its message as written, anything else as `JSON.generate` writes it; a handler that raises gets an error result saying "The tool failed: " and the message | TOOL-01, TOOL-05. The block is Ruby's way to pass behaviour; a `Data` would compare and dump its `Proc`. A failure the handler means (a business rule) is a value it returns, as .NET's and Go's handlers return an error result; an exception stays the unexpected case (ruby/CLAUDE.md), and the prefix tells the model which it got. With one duck type for both inputs the tool needs no type switch; a `Schema` input is the form an MCP tool (Ruby S11) needs. The kind has no default, so no tool runs concurrently by accident |
| The tool pipeline runs a reply's calls on one thread of its own; each read call runs on a thread it starts, joined before the next write and before it returns; a write and every approval run on the pipeline's thread itself. Its threads raise where they are joined and print nothing as they end. If the pipeline fails (a handler raised beyond `StandardError`, or a bug), it cancels the reads still running and joins each before it closes its queue | TOOL-03 and ARCHITECTURE §5.2 without a scheduler: the pipeline's thread is the only one that touches its result table, and a read's thread only returns its result through `Thread#value`. Nothing outlives the run, and the run never waits on a queue nobody closes |
| The pipeline's events go to a `Thread::Queue`, closed by the pipeline when it has answered every call; the run drains it on the caller's thread, yielding each event, then takes the results with `Thread#value` | R11. The pipeline never waits for the host, so an approver that waits for an answer from the host's event block meets it in either order |
| A host that leaves the block while a reply's calls run (`break`, an exception) cancels the run's `Cancellation`, then waits for the pipeline; with no pipeline yet, one starts on the cancelled run, so every call still gets its result. The results are appended, not reported | AGT-05, R10. The run's token is the host's (one per run); a linked child token would need the on-cancel callback, which Ruby S04 adds for its stream |
| The approver contract is `_Approver#approve(tool, call, cancel:)`, returning an `Approval` (approved, and a reason the model is told on a denial). An approver that raises denies the call, its message the reason: the pipeline rescues `StandardError` around it | TOOL-04, GEN-04. The approver runs on the pipeline's thread, where the host cannot rescue it; this is a boundary beyond the three ruby/CLAUDE.md names, like Go's recovered approver panic |
| A result is cut at 64,000 characters (Ruby's `String#length`, code points), with a note giving its length; audit text at 4,000 characters | TOOL-06, AUD-05. Ruby counts text in characters, as .NET does; neither cut splits a character |
| `Agent#redact` replaces every form of every secret by `[redacted]`: as written, and inside a JSON string with no escapes beyond JSON's, with `<`, `>` and `&` escaped (Go), with every character beyond ASCII escaped, and with .NET's escapes, each in lower- and upper-case hex and with `/` as written or escaped. It marks every character any occurrence of any form covers, then replaces each covered stretch once | D13. A tool's result may quote a secret as any JSON writer escapes it; marking characters redacts secrets that overlap, touch or contain one another whole, whatever their order, without merging spans. Redacted: tool results, the calls the tool events and the approver see, a completed run's text, a stopped or failed run's detail, and the audit trail |

## How Ruby realizes the runtime model

Each row of ARCHITECTURE §5.3, and the layers of §3, in Ruby terms. .NET's and Go's design notes hold the same table.
Rows marked *planned* are the decisions the slice in brackets builds; it replaces the mark with what it built.

| ARCHITECTURE element | Ruby |
|---|---|
| Streaming | The model's `stream` yields `TextDelta`, `UsageReported`, `Retried`, `ConversationCompacted` and `ToolResultsCleared` as they arrive; the run's `ModelCall` yields the same values on to the host's block at once. The Claude model streams every request, on the SDK's beta messages API |
| Event order | The run yields on the caller's thread, in the order things happen; the result is `run`'s return value, so it always comes after the last event. A step's messages are all appended before the first `ConversationAppended` |
| Consuming a run | `Agent#run` yields each event to its block and returns the result (`Completed`, `Stopped` or `Failed`) (R10) |
| Host stops consuming | Leaving the block (`break`, an exception) unwinds the run on its own thread and `run` returns no result. A reply cut off is not appended; a reply with calls already appended gets its calls' results in an `ensure`, without yielding again, so every call stays answered; the conversation is released in an `ensure`. While a reply's calls run, it cancels the run and waits for the tool pipeline in an `ensure`, then appends every call's result (R10) |
| Asynchronous I/O | Blocking calls: the model on the run's thread (the caller's); the approver and writes on the tool pipeline's thread; each read on a thread of its own. The model, the approver and the handlers take the run's `Cancellation` (R10, R11) |
| Concurrency | Model calls of a run are one after another on its thread. The agent is frozen, its tools and instructions frozen values; many runs share it, each on its own conversation and thread (AGT-04, tested with 100 threads). Each memory store is shared by many runs and guards its state with its own `Mutex`, tested by eight threads writing and renaming in one scope, and by threads switched inside each call while they write, rename and list |
| Concurrent reads | A thread per read call, joined (`Thread#value`) before the next write and before the pipeline returns; I/O releases the VM lock, so reads overlap (R11) |
| Hand-over | The tool pipeline runs on its own thread and pushes its events to an unbounded `Thread::Queue`, which it closes when every call has a result; the run pops and yields them as they come (R11) |
| Cancellation | `Officina::Cancellation` (`cancel`, `cancelled?`, `on_cancel`), passed as `cancel:`, one per run; the run checks it before each model call and when a stream ends, the Claude model at each event and before each attempt, and its wait between attempts wakes through `on_cancel`. A signal trap only pushes to a queue an owned thread reads (R10): Bookshop's console traps `INT` for its life, and its watcher thread cancels the reply in progress; an approval prompt and the approver both stop waiting through `on_cancel` |
| One run per conversation | `Conversation#hold` takes the conversation's `Mutex` with `try_lock`; a second run raises an `Officina::Error` |
| Ownership | The run joins the tool pipeline's thread, in an `ensure` when the host leaves; the pipeline joins its reads' threads in an `ensure`. Nothing outlives the run, and the thread-leak check fails any test that leaves a thread running (R11). An MCP client's threads and child process are its own: each request's thread ends with the request, and `Client#close` stops and reaps the server and joins its readers |
| Persistence points | `ConversationAppended` for each message, yielded while the run waits; `Conversation#to_json` is safe to call from the block. Bookshop's `Session` saves the session there, on the console's thread, and once more when the run returns. A summary is stored once its stateless run returns, on the console's thread, with its cost |
| Time | The agent's `clock:`, a callable returning a `Time` (`Time.now` by default, a fake in tests), gives audit times, tool durations, a run's duration and time budget, and every telemetry time (spans, events, durations, the approval wait, time to first token); the Claude model waits between attempts through a `wait:` callable, real by default, recorded in tests; the MCP client's waits (the connect deadline, a server's exit, its error output) read a monotonic `clock:` callable, fake in tests (R12) |
| Composition root | `Bookshop.build(input:, output:, model:, summarizer:, env:, clock:, telemetry:)`, called by `exe/bookshop` and by the console's end-to-end tests (R5): a `Database` on `BOOKSHOP_DATABASE` or the compose file's database, the shop and its nine tools over it, the approver, the audit table, the session store, the budgets, the telemetry (OTLP unless given), the agent (Claude unless a model is given, the database password as a secret, the table as its sink, the telemetry's `Officina::Telemetry`) and the summarizer (Claude unless a model or nil is given) and the console with `/audit`'s view, returned as an `Application` to run and close, which closes the database and sends the telemetry left. Nothing connects until a reply needs it. Tests replace only the model, the input and output, the clock and the exporters |
